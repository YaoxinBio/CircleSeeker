# CircleSeeker 1.5.2 release preparation

Status: repaired candidate; final publication and full dataset acceptance are
pending. Evidence checkpoint: 2026-09-11, release source `e7e9ed0`.

GlioSarc_P01_Tumor completed 16/16 on 2026-09-11 and reports 1,158,188 eccDNA.
That run was staged across three sources - steps 1-8 on `44c79b8`, steps 9-14 on
`a662ad7`, the last two steps on the current candidate - so it is not a run of
this release from end to end, and its inferred multi-segment CeccDNA structures
predate the determinism fix.

Two things this candidate changes relative to `a662ad7`, both after the accepted
repairs:

- Deliverables no longer vary between runs. Two places let the iteration order
  of a set of strings decide a written result. See CHANGELOG.md.
- Scale work across ten modules. Verified equivalent: an end-to-end comparison
  of two seed-varying runs against a build with none of the optimisations gives
  byte-identical deliverables on the Arabidopsis simulation. That is one sample;
  broader end-to-end coverage has not been run.

This candidate incorporates the accepted repair source
`44c79b8eafdb1f60f949d69c9eeab12a69ce570b` and its performance-only successor
`a662ad74e1cf984af0417017a36572e3a725c934`. Active maintenance moves to
YaoxinBio/CircleSeeker while preserving original authors, licenses and history.
The previous GitHub draft at `5b6a79f`, based on rejected repair `055110f`, is
obsolete and its assets must be replaced before publication. See
[provenance](../../PROVENANCE.md) for the exact computation-to-release mapping.

## Changes affecting results

- Repeat candidates from the same read retain their own sequence, length and RCA
  support. Missing candidate metadata cannot borrow another repeat's metadata.
- Classification and deduplication preserve segment direction and circular
  traversal order. Existing CD-HIT clusters retain their baseline role; the
  preliminary patch's additional cluster partition and exact-consensus grouping
  are removed. Coordinate-only merging retains the original 10 bp tolerance
  while requiring equivalent directed cycles.
- A selected alignment spanning the full consensus cannot be combined with extra
  loci into a nonoverlapping chimeric partition. Inferred paths and cycles follow
  retained graph edges; segment strands survive curation and sequence extraction.
- Per-read RCA support is reconstructed from candidate support, separately from
  the molecule aggregate. This is RCA support, not genomic copy number.
- Cecc BEDPE contains N junctions for N segments, including the closing junction;
  endpoints respect strand. Consumers assuming N−1 junctions must adapt.
- LAST identity is measured from alignment strings. Unavailable LAST MAPQ,
  low-MAPQ and associated confidence values remain missing.
- Packaging rejects inconsistent confirmed Cecc sequence lengths; final FASTA
  excludes inferred candidates removed from the final catalogue.

Counts, IDs, directions, support values and benchmark metrics can change. The
endpoint numeric-comparison fix was already present in historical v1.5.1.

## Installation compatibility

Support aggregation now indexes cluster representatives once and writes back
fields in bulk, removing the per-cluster full-table scans that stalled GS.
Candidate support and RCA accounting retain the existing rules. Progress is
logged every 10,000 clusters. Actual GS U/M/C subsets matched the frozen repair
exactly, and the support loop processed one million synthetic clusters in
281.471 seconds on fat2. This timing does not cover an entire GS pipeline.
See [performance validation](../development/dedup-support-performance.md).

The installed command is `circleseeker`. A second entry point named only by
different capitalization (`CircleSeeker`) caused uninstall/reinstall failures on
case-insensitive macOS filesystems. It is removed from distribution metadata;
use the lowercase command in scripts, including on Linux. The Python API and
computational implementation are unchanged by this packaging correction.

Source distributions now include provenance, citation and release documentation,
regression tests and their tracked fixtures alongside the implementation.

## Validation of the frozen repair source

- Linux/Python 3.12: 1,293 tests passed, one deselected; coverage 72.49%; mypy
  passed 59 source files. These are checks of `44c79b8`, distinct from new
  release-artifact installation checks and the older draft's CI.
- All 55 previously flagged real-data records passed targeted replay from saved
  original evidence. Two complete raw-input runs and the affected final inference
  stages were separately verified before continuing the full cohort.
- All 27 complete raw-input benchmarks passed output-integrity checks. Against
  original v1.5.1, Overall TP was 328,006 → 328,004 and FP 4,777 → 4,756.
  Equal-scenario mean F1 was 0.97145185 → 0.97145926. At the evaluator's four-decimal
  precision, 23 Overall F1 values were unchanged, three improved and one decreased.
- Three scenarios had a small decrease in at least one reported metric: human
  UMC rep3/10X and rep3/50X each lost one Cecc TP; rep3/30X gained one Uecc FP
  while its Overall FP fell by two. The author accepted small deviations and
  requested all computations finish with differences retained in the record.
- In the same 19 scenarios that exposed the rejected repair's +350 FP, the current
  source has unchanged TP (153,809) and three fewer FP (1,274 → 1,271) than v1.5.1.
- Thirty-two of 33 real libraries completed with `44c79b8`: 2,182,394 → 2,182,115
  calls. Uecc increased by 12 and Mecc by 3; Cecc decreased by 294 (52 Confirmed,
  242 Inferred). Integrity reports passed; an independent summary-count audit
  agreed. These differences have not all been attributed record by record and
  cannot be labelled TP/FP without a per-molecule truth set.
- The `a662ad7` performance source passed 1,296 selected local tests; two
  LAST-dependent tests were skipped and one test was deselected. The three
  bounded GS U/M/C comparisons preserved values, dtypes, order and CSV bytes.

Benchmark scoring follows the existing matching rules and does not independently
validate strand or circular order. Equal counts also do not imply identical rows
or sequences. The detailed repair contracts and replay evidence are documented
in [the development report](../development/cecc-integrity-fix.md).
